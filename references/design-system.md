# 精密技术感设计规范

## 核心与边界

参考入口：https://resend.com/ 。借鉴的是克制、精确的技术产品语言，不依赖其当前网页结构；未附带官网代码、截图或品牌资产。产品名称、图标、文案与内容必须属于用户项目。

与 Radix Workbench 的区别：本方向重视产品表达、代码和运行状态的精确呈现；Workbench 更重视表格、复杂表单与长时间操作。与 Craft Clarity 的区别：此处对齐更紧、工具化更强、代码和系统元数据占比更高。

## 设计变量

可选起点位于 `../assets/tokens.css`。将 `data-style="mono-signal"` 放在应用根元素，在同一元素设置 `data-theme="dark"` 启用深色。变量仅作用于该子树；迁移到既有主题系统也可。

| 角色 | 明色 | 暗色 | 用法 |
| --- | --- | --- | --- |
| 画布 / 表面 | #fafafa / #ffffff | #141414 / #1c1c1c | 只用少量层次 |
| 正文 / 次要字 | #171717 / #525252 | #f5f5f5 / #b8b8b8 | 不用低透明度代替正文色 |
| 品牌强调 | #176347 | #8ed8b3 | 主操作与链接，避免刷满背景 |
| 边界 | #dedede | #3f3f3f | 装饰分隔；输入框使用更强的 control-border |

默认强调色可替换；替换后检查文字、按钮、焦点和禁用状态。正文至少 4.5:1，大号文字和可操作边界按适用 WCAG 要求检查，细分隔线不充当输入框唯一边界。

- 字体：系统无衬线 + 中文系统字体；代码使用 ui-monospace。基础字号 16px，工具标签 13-14px，页面标题 28-36px，hero 仅在需要时 48-64px。小屏用明确断点调整字号，不用 vw 或负字距。
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px。内容宽 1120-1200px；文档正文 68-76ch，侧栏约 240px。
- 控件：高度 36-40px；触屏主要目标至少 44px；圆角 4-6px。边界 1px，阴影只为浮层建立层级。
- 动效：120-180ms，主要用于状态变化。尊重 reduced-motion，不用持续闪烁的终端光标制造噪声。

## 按项目选择布局

### 开发者产品网站

首屏显示名称、实际类别、一个主行动，以及真实产品视图或有明确演示属性的接口结果。后续按用户决策需要排能力、集成、价格；不自动添加客户 logo 墙或无依据的可靠性承诺。若有 hero，媒体使用真实/生成位图或实际可交互产品场景，避免 SVG 网格、渐变光晕和两块并列卡片的模板。

### 文档与 API 参考

侧栏 / 正文 / 可选页内目录；代码块显示语言、复制按钮、合理换行与溢出。窄屏把导航收进可展开区域，代码块可以独立横向滚动，页面本身不横向溢出。版本选择必须关联真实内容或明确演示，不做无效下拉。

### 控制台

上方项目与环境切换，主区域放近期记录或任务列表，详细信息在侧栏或详情页。指标只是辅助，不用营销巨字占据首屏。ID 可以截断显示，但必须提供查看完整值和复制途径。

## 组件与行为

- 主按钮：实色高对比；次要按钮：中性边框；危险动作单独语义颜色。loading 保留原宽，防重复提交，结果用真实操作反馈。
- 状态：成功、等待、失败具有图标/文字与颜色双重信号。空状态给可执行动作；错误保留上下文并提供适当重试。
- 记录表格：时间、状态、目标、动作各有稳定列；排序有方向提示，筛选能清除，分页与筛选状态一致。
- 复制：成功反馈短暂且可读；失败时允许选择原文，不把未完成复制标为成功。
- 弹层：焦点进入和返回；Escape 可关闭非阻断弹层；表单提交错误留在对应字段旁。

## 验收重点

至少检查 375px、768px、1440px 布局，以及键盘操作、超长代码/ID、空/错/加载状态。若提供明暗切换，两种都测试。不以截图代替交互测试；没有浏览器条件时准确交代已做与未做的检查。
